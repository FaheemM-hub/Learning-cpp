General Problem-Solving Techniques
============================================================================

	1. Always Have a Plan
	
		- Don't engage in directionless activity.
		- Planning allows you to set intermediate goals and achieve them, without a plan you have to solve the whole problem at once.
	
	2. Restate the Problem
		
		- Sometimes problems that look very difficult may seem easy when stated in a different way (Like circling the base of a hill you need to climb and finding the easiest angle/slope to approach).
	
	3. Divide the Problem

		- Dividing a problem can lower difficulty by an order of magnitude (like taking 100 files, dividing them into 4 groups to be alphabetized separately then compiled versus sorting 100 individual files).
	
	4. Start with What You Know

		- When you start working on a programming problem, complete any parts you already know how to code. Having a partial solution will spark ideas on solving the rest of the problem.

	5. Reduce the Problem

		- You can reduce the scope of the problem, by either adding or removing constraints.
		- Programmers often write code solving individual aspects of a problem, then combine various pieces of code into a unified whole.
	
	6. Look for Analogies
		
		- Similarities between past problems and current problems can be exploited to help resolve current problems more easily.
		- Every successful program you write is a potential source of analogies for future problems
	
	7. Experiment

		- A controlled process, in which you hypothesize what will happen with certain code executed. Through testing your hypothesis you derive new information to correctly solve your original problem.
	
	8. Don't get Frustrated

		- When frustrated you won't think as clearly, you don't work as efficiently, and everything takes longer and seems harder.
